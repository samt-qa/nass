# Changelog

All packages (Dart `nass`, npm `@samt-qa/nass`, Packagist `samt/nass`, crates.io `nass`) share one version and one spec.

## Unreleased

### Benchmarks (all packages)
- The benchmarks now run on real text: the first 1 Mi UTF-16 units (about 2 MB of UTF-8, 1,658 hadiths) of the vocalized Sahih al-Bukhari, built by `tools/bench-text.mjs`. Before, they repeated one sentence, and the READMEs wrongly called that "1 MB of Sahih al-Bukhari". All performance tables were re-measured in one session.

### Rust 0.4.0 (breaking, not yet published)
- `Normalized::start` and `Normalized::end` are now `Vec<u32>` (were `Vec<usize>`): half the memory for the offset map. `normalize_with_map` panics on texts of 4 GiB or more. `source_range` still returns `Range<usize>`.
- `normalize` and `normalize_into` no longer build source spans at all (same pipeline code, span tracking compiled out): about 20-25% faster on the Bukhari benchmark (search: 18.8 → 15.2 ms). `normalize_with_map` is 2-9% faster and its working buffer uses 12 instead of 20 bytes per code point.
- No behaviour change: all shared vectors pass, differential test 0 mismatches / 172,463.

## 0.3.1 (Rust only)

- docs.rs builds the documentation with all features, so the experimental `isnad` module is documented.
- No code change; behaviour is identical to 0.3.0.

## 0.3.0 (Rust)

### Rust package (new, published on crates.io)
- `packages/rust`, crate `nass` 0.3.0: SPEC v0.3 in Rust, no runtime dependencies, `#![forbid(unsafe_code)]`, MSRV 1.70.
- `normalize`, `normalize_into`, `normalize_with_map` (with `Normalized::source_range`), `find_all`, `contains`, `highlight`, `name_key`; `isnad::split_isnad` behind the `isnad` feature.
- Offsets are UTF-8 bytes; `byte_to_utf16_offset`, `byte_to_char_offset` and `utf16_to_byte_offset` convert to the other packages' units.
- Passes all 1,554 shared vectors; differential test against the oracle: 0 mismatches / 172,463 (`node tools/differential.mjs rust`).
- Character tables are generated by `tools/gen-tables.mjs` (`packages/rust/src/tables.rs`) and covered by `--check`.
- CI: fmt, clippy and tests on stable and 1.70, on Ubuntu and Windows.

### Normalization
- No change.

## 0.3.0

### splitIsnad (still experimental)
- New rules: «أنه أخبره عن», «كان يحدث أن», «أخبرني عن» after a name, «أن عائشة زوج النبي ﷺ قالت», «فاطمة بنت رسول الله ﷺ», «قال قال يعني رسول الله ﷺ», a second chain after «أن رسول الله ﷺ قال ح», Hammam's sahifa («هذا ما حدثنا أبو هريرة… فذكر أحاديث منها وقال رسول الله ﷺ»), «عن مولى لأبي سعيد», «لقيت» as a narrative verb, narrative verbs now end a name, and «قال قال رجل…» keeps «قال رجل» in the matn.
- «أن فلان رضي الله عنه» followed by a story (not a chain) is no longer taken as a link.
- Measured on a new sample of 300 hadiths, labelled blind by two annotators and held out until the design was frozen: dev 98.0% (490/500), **held-out test 88.3% (265/300)**. Details in `docs/corpus.md` and SPEC §14.

### Normalization
- No change. Keys from 0.2 stay valid.

### Test vectors
- 1,554 shared cases (was 1,254): 300 new isnad cases, reviewed and approved (SPEC §14).

## 0.2.0

### Normalization (SPEC §13)
- **U+06E7 ARABIC SMALL HIGH YEH becomes «ي» at the `search` level** instead of being deleted. In Uthmani script it stands for an omitted ya: «ٱلنَّبِيِّـۧنَ» now gives «النبيين» (was «النبين»).
- **ZWNJ (U+200C) is kept at the `clean` level**, so Persian and Urdu words keep their shape («می‌خواهم»). `search` removes it when it touches an Arabic letter.
- Keys produced by `search`, `loose` and `nameKey` change for text that contains U+06E7 or ZWNJ. Rebuild stored keys.

### splitIsnad (still experimental)
- New lexicon and rules: «قال قال فلان», «مولى» followed by a name, «صاحب رسول الله ﷺ», «نبيكم», «واللفظ له / لفلان», «قراءة عليه وأنا أسمع», «حدثهما / أخبرهما», «سمعته يقول», a second chain after «عن النبي ﷺ ح», and first-person narrative verbs («أتيت», «سألت»…) that never start a narrator's name.
- Measured on a new sample of 300 hadiths, labelled blind by two annotators before any change: dev 98.3% (295/300), **held-out test 88.0% (176/200)**. The 0.1 algorithm scores 87.5% on the same held-out set. Details in `docs/corpus.md`.

### Test vectors
- 1,254 shared cases (was 952): 300 new isnad cases, and new normalization cases for ZWNJ.
- All v0.1 cases were reviewed and approved (SPEC §12).
